# Grafting this keymap into `beekeeb/zmk-keyboard-toucan`

Generated by keyboard-manager from `beekeeb 36key.vil` for **beekeeb Toucan (dongle mode)**.

This export is **not** a standalone zmk-config. beekeeb Toucan (dongle mode) needs shield
definitions, Zephyr modules and `.conf` files that live in
<https://github.com/beekeeb/zmk-keyboard-toucan> (branch `prospector-dongle`), and
those describe hardware a `.vil` knows nothing about — displays, trackpads, LED
widgets. So the only file here that belongs in a build is the keymap.

## Steps

```sh
git clone --branch prospector-dongle https://github.com/beekeeb/zmk-keyboard-toucan.git
cp config/toucan.keymap zmk-keyboard-toucan/config/toucan.keymap
```

Then build. **Do not** copy anything else over: their `.conf` carries hardware
settings this exporter cannot know about, and overwriting it is a silent
downgrade.

This layout uses mouse keys, so the firmware needs `CONFIG_ZMK_POINTING=y`. Check the shield's `Kconfig.defconfig` before adding it to a `.conf` — a board with a trackpad almost certainly enables it already.

## What to build, and what to flash

```yaml
# dongle — the only image that carries the keymap
- board: seeeduino_xiao_ble
  shield: toucan_dongle rgbled_adapter dongle_screen
  snippet: studio-rpc-usb-uart
  cmake-args: -DCONFIG_ZMK_STUDIO=y
# left half (peripheral) — a keymap change does not touch it
- board: seeeduino_xiao_ble
  shield: toucan_left rgbled_adapter toucan_pet
# right half (peripheral, owns the trackpad) — a keymap change does not touch it
- board: seeeduino_xiao_ble
  shield: toucan_right rgbled_adapter
```

- **dongle — the only image that carries the keymap**
- **left half (peripheral) — a keymap change does not touch it**
- **right half (peripheral, owns the trackpad) — a keymap change does not touch it**

A keymap change only affects the image(s) marked as carrying the keymap
(toucan_dongle + rgbled_adapter + dongle_screen) — the
others keep the firmware they already have.

## If the keyboard still behaves the old way after flashing

ZMK Studio's stored keymap **overrides the compiled one**. Once Studio has
written a keymap to the device, flashing a new `.keymap` changes nothing until
you connect Studio and run **Restore Stock Settings**.
